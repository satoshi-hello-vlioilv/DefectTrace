# ロット表の読み込みの速さ・読み直さない作り（版 4.3.0・画面に出ない改良）

利用者の依頼: 「リスト化は一度実行したデータは保持して、追加で開いた月や日付の階層単位で追加される形にして、同じところを何度も読み取りなおさない
ようにしてほしい。リスト化の速度がいまいちで遅いので、並列処理・バックグラウンド処理・処理言語の最適化（Rust か Python まで）まで考え検討してほしい」

## 測り方（評価関数）

- `program/tools/lotlist-bench.mjs <設備>`: 本物の画面（試しの入口）で 5 つの場面を測る。時間・裏が読んだバイト数と回数（`/proc/<pid>/io` の
  rchar・syscr。共有フォルダ〈Box・ネットワーク〉ではここが時間になる）・画面のいちばん長い止まり・裏のメモリ
  1 初回 / 2 もう一度（別の設備を見てから戻る）/ 3 画面の開き直し / 4 アプリの起動し直し（同じ作業場所）/ 5a 1 日 → 5b その月へ広げる
- `desktop/examples/listbench.rs <設備>`: 1 ロットを 1 本で読むときの、手順ごとの時間（walk・defs・insp・cond・kinds・values）
- 試しの設備: 利用者の LS3 の本物のロット（2026_10_24_19_42_05。解析結果から .dat を全バイトで作り直し、本物の InspectDataInfo.xml・
  COND0005.xml・Common.xml を置いた物）を 600 個（2026/08・09 の 60 日 × 10）。手元のディスク・芯 4 本

- 画面を開き直す・アプリを起こし直すたびに、同じロットを全部読み直す（値を覚えるのは画面の中だけ）
- 1 ロットの値を作るのに 5.76 ms（1 本）。内訳: 定義の XML（56 KB・Shift_JIS）を読み解く 2.46 ms（全ロットで中身は同じなのに毎回）・
  条件の XML を (鍵, 値) に平らにする 2.34 ms（うち XML を字にするとき、正規表現を毎回作って 0.94 ms）・値を作る 0.61 ms（鍵ごとに正規表現を作る）
- 条件の XML の列を 1 つ引くたびに、ロットのフォルダと cond フォルダの一覧を読み直す（1 ロットで 16 回。共有フォルダでは 1 回ごとに行き来の待ち）
- 範囲を変えるたびに、列の目録の見本 5 ロットで DETECT_INFO（2.9 MB）を全部読む（件数を数えるため・分類別の列の見本のため）
- 画面: 40 ロットずつの問い合わせを 1 本ずつ順に投げる。LotScope の表示列の部品の get が呼ばれるたびに設定（83 列ぶん）を JSON で写し、
  セル 1 つごとに呼ばれるので 300 行の描き直しに約 3.5 秒（5b の止まり）

## 案（7 案。方向: 読み直さない〈覚える場所〉・1 ロットを軽く・並べ方・先に読む・言語）

| 案 | 中身 |
|---|---|
| A 1 ロットを軽く | フォルダの一覧はロットを開いたときの 1 度だけ（LotRes::glob）・件数は頭とファイルの大きさから（DETECT_INFO を読まない）・重い列の見本は表示列の窓を開くときだけ・定義の XML は中身で使い回す・正規表現は 1 度だけ作る・[*] の無い鍵は字の一致で引く |
| B 裏で覚える（作業場所の lotvalues.json） | ロット × 列（ファイル・鍵・倍率・形）の値を残し、起動し直しても読み直さない。ロットの INSP_INFO の大きさ・更新時刻が変われば読み直す。アプリの版・設定が変われば全部捨てる。「↻ 読み直す」で範囲を読み直す |
| C 画面の問い方 | 先に「覚えている値だけ」を 1 度に問い（読まない）、覚えに無いロットだけを 40 ずつ 3 本同時に読む。表示列の部品の設定を、変わるまで使い回す |
| D 採用案: A ＋ B ＋ C | 全部 |
| E 画面で覚える（WebView の IndexedDB） | B の代わりに画面の中に残す |
| F 裏で先読み | 木で日・月を開いたとき、その下のロットを裏で読んでおく（ロット表を開く前に） |
| G Python に書き直す | 値を作る所を Python で（1 本・スレッド 8・プロセス 8） |

### 作らなかった案の、効きの上限（測った数）

- **E 画面で覚える**: D の 3・4 で値を問う所は、覚えから返す問い合わせ 1 回（600 ロットで 0.01 秒・読んだ量 0）。残りの 0.38〜0.42 秒は
  ロットを集める・列の目録・表示項目を読む所で、E でも同じにかかる。E で縮むのは 0.01 秒以下。書き出し（CSV・Excel）・裏の問い合わせには使えない
- **F 裏で先読み**: D の 5a（0.33 秒）のうち、値を読む所は 10 ロット × 1.7 ms ÷ 8 本 ≒ 0.002 秒（手元）。共有フォルダでは 1 ロット
  約 106 KB・開く 9 回の分が縮むが、画像を見ている間に裏で共有を読むので、画像の読み込みと回線を取り合う
- **G Python**: 同じ 600 ロットで、Python は 1 本 2.42 秒・スレッド 8 本 3.31 秒・プロセス 8 本 0.75 秒
  （確かめ〈多量・上限・時刻〉の計算をしない、より少ない仕事で）。Rust（A の後）は 1 本 1.0 秒（1.70 ms × 600）・裏（並べて読む・同じ 17 列）で 0.34 秒（覚えからは 0.01 秒）。
  配る exe に Python を入れる重さ（数十 MB）もかかる
